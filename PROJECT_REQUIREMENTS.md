# iPro - Donation Management System
## Project Requirements Document

### Project Overview
A responsive web application for managing charitable donations for **Helping Hand for Relief and Development**, specifically focused on the Jamaica Hurricane Emergency Relief campaign. The system will handle multiple payment methods, donation types, and provide a seamless user experience across all devices.

## 2. Personal Information Section

### 2.1 Required Fields
All fields are mandatory for new donors:

| Field | Type | Validation |
|-------|------|------------|
| **Name** | Text | Full name required |
| **Email** | Email | Valid email format, used as unique identifier |
| **Phone** | Tel | Valid phone number format, can be used as unique identifier |
| **Street Address** | Text | Complete street address |
| **City** | Text | City name |
| **State** | Dropdown/Text | State/Province |
| **ZIP** | Text | Postal/ZIP code |

### 2.2 Auto-Population Feature
- System uses **Email** or **Phone Number** as unique identifiers
- For returning donors:
  - When email or phone is entered, system auto-populates previous information
  - Saves time and improves user experience
  - Users can update their information if needed
- For new donors:
  - All fields must be filled manually
  - Information is saved for future donations

## 4. Payment Method Selection

### 4.1 Available Payment Options

#### Option 1: Cash
- Simple checkbox selection
- Display confirmation page after selection
- No additional fields required
- Admin will need to manually process and confirm receipt

#### Option 2: Check/Cheque
- User selects "Check" option
- Additional fields appear:
  - **Check Number** (CC/CHECK #)
  - **Expiration Date** (EXP)
  - **CVC Code** (if applicable)
- **Bank Information Section** (appears when check is selected):
  - Bank Name
  - Account Number
  - Routing Number
- **Photo Upload Feature**:
  - Prompt user to take/upload photo of check
  - Use device camera or file upload
  - Store image with donation record
  - For record-keeping and verification

#### Option 3: Online Payment (Stripe Integration)
- Display major card brand icons (Visa, MasterCard, Amex, Discover, etc.)
- Redirect to Stripe payment gateway
- Secure card information entry:
  - Card number
  - Expiration date
  - CVV/CVC code
  - Cardholder name
  - Billing ZIP code
- Real-time payment processing
- Immediate confirmation upon success

### 4.2 Stripe Payment Gateway Integration

#### Security Requirements
- **PCI DSS Compliance**: All card data handled by Stripe
- **Tokenization**: Never store raw card data
- **SSL/HTTPS**: All transactions encrypted
- **3D Secure**: Support for enhanced authentication when required

#### Implementation
- Use Stripe.js for frontend integration
- Implement Stripe Elements for secure card input
- Server-side API calls for payment processing
- Webhook handling for payment confirmations

#### Transaction Flow
1. User enters card details in Stripe-hosted form
2. Token generated by Stripe
3. Token sent to server
4. Server processes payment via Stripe API
5. Confirmation returned to user
6. Email receipt sent automatically

## 5. Backend Requirements

### 5.1 Database Schema

#### Users/Donors Table
```
- id (primary key)
- name (string)
- email (string, unique, indexed)
- phone (string, indexed)
- street_address (string)
- city (string)
- state (string)
- zip (string)
- created_at (timestamp)
- updated_at (timestamp)
```

#### Donations Table
```
- id (primary key)
- user_id (foreign key)
- amount (decimal)
- donation_type (enum: zakat, sadaqah, general)
- payment_method (enum: cash, check, online)
- payment_status (enum: pending, completed, failed)
- transaction_id (string, nullable) - Stripe transaction ID
- check_number (string, nullable)
- check_photo (string, nullable) - file path
- bank_name (string, nullable)
- account_number (string, nullable)
- routing_number (string, nullable)
- campaign (string) - e.g., "Jamaica Hurricane Relief"
- notes (text, nullable)
- created_at (timestamp)
- updated_at (timestamp)
```

#### Payment Transactions Table
```
- id (primary key)
- donation_id (foreign key)
- stripe_payment_intent_id (string, nullable)
- stripe_charge_id (string, nullable)
- amount (decimal)
- status (string)
- payment_method_details (json)
- receipt_url (string, nullable)
- created_at (timestamp)
```

### 5.2 Security Implementation

#### Data Protection
- **Encryption at Rest**: All sensitive data encrypted in database
- **Encryption in Transit**: Enforce HTTPS/SSL for all connections
- **Password Hashing**: Use bcrypt or Argon2 for admin passwords
- **Data Sanitization**: Prevent SQL injection attacks
- **XSS Protection**: Sanitize all user inputs
- **CSRF Protection**: Implement CSRF tokens for forms

#### Payment Security
- **PCI DSS Compliance**: No card data stored on server
- **Stripe Integration**: Use Stripe's secure payment processing
- **Webhook Verification**: Validate Stripe webhook signatures
- **API Key Security**: Store Stripe keys in environment variables

#### User Privacy
- **GDPR Compliance**: Allow users to request data deletion
- **Privacy Policy**: Clear documentation of data usage
- **Consent**: Obtain user consent for data storage
- **Access Control**: Role-based access for admin functions

### 5.3 File Storage
- **Check Photos**: Secure storage for uploaded check images
- **Directory Structure**: Organized by date/user
- **Access Control**: Private storage, admin-only access
- **Backup**: Regular backups of uploaded files

## 7. Notifications System

### 7.1 Donor Notifications

#### Email Confirmation (Immediate)
Sent automatically after donation completion:
- **Subject**: "Thank you for your donation to [Campaign Name]"
- **Content Includes**:
  - Donor name
  - Donation amount
  - Donation type (Zakat/Sadaqah/General)
  - Payment method
  - Transaction ID (for online payments)
  - Date and time
  - Organization contact information
  - Tax receipt information (if applicable)
- **Attachment**: PDF receipt (optional)
- **Footer**: Unsubscribe option, privacy policy link

#### Payment Confirmation (For Online Payments)
- Stripe-generated receipt
- Link to view transaction details
- Payment method (last 4 digits of card)

#### SMS Notification (Optional)
- Brief confirmation message
- Donation amount and reference number
- Thank you message

### 7.2 Admin Notifications

#### New Donation Alert
- **Email Notification** to admin when:
  - New donation is received
  - Payment status changes
  - Large donation is made (threshold configurable)
- **Content Includes**:
  - Donor name and contact
  - Donation amount and type
  - Payment method
  - Timestamp
  - Link to view full details in admin dashboard

#### Daily Summary Email
- Total donations for the day
- Number of new donors
- Payment status summary
- Any failed transactions requiring attention

#### System Alerts
- Failed payment notifications
- Database backup confirmations
- Security alerts (if any suspicious activity)
- Stripe webhook failures
